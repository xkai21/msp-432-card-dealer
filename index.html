Short Project Description

Building an Embedded System That Performs a Real Task

For my final Microcontroller project, I designed and built an automated card dealing system using the MSP432 microcontroller. The goal was to create a robot that could dispense playing cards in a controlled sequence for a card game.

The system used a 3D-printed card dispenser, a DC gearbox motor, a servo, a TB6612FNG motor driver, and programmed logic on the MSP432 to coordinate the card-dealing motion. The feeder motor was controlled with GPIO direction pins and a PWM signal generated by TimerA, while the servo added another controlled mechanical movement to the system.

Technical Architecture

How the System Worked

AIN1 / AIN2 for Direction PWMA for Speed Control TimerA PWM Output One-Card Feed Logic

The TB6612FNG motor driver handled the feeder motor, with AIN1 and AIN2 connected to MSP432 output pins and PWMA connected to a TimerA PWM output. The software included dedicated functions to move the feeder forward, reverse it when needed, stop it safely, dispense one card at a time, and coordinate that motion with the servo.

Original Conceptualization

From Class Robot Platform to Poker-Style Dealer

Initial Goal

The original concept was a poker-style card dealing robot that could eventually handle full game flow, including dealing to players, discard actions, the flop, turn, and river.

Mechanical Direction

I started with the robot platform from class and added a separate 3D-printed card dispenser. A DC gearbox motor was chosen because it was compact, simple to control, and strong enough to push cards through the feeder, while a servo added precise controlled movement to support the overall mechanism.

Embedded Design Choice

The MSP432 controlled the mechanism through a TB6612FNG motor driver because a microcontroller pin cannot safely power a motor directly. This let the software manage motor direction, servo movement, timing, and future expansion into a state-driven game system.

Obstacles Faced

Where the Real Engineering Work Happened

  • Wiring the external motor driver correctly required separate motor power, logic power, and a shared ground between the robot battery, MSP432, and TB6612FNG.
  • Tuning the dispense timing was difficult because too much motor runtime could release multiple cards, while too little runtime could leave a card only partially fed.
  • Integrating the feeder logic into a larger robot state machine required careful code organization so the robot would not move unintentionally while the dispenser was active.
  • Coordinating the servo with the feeder motor added another layer of timing work, since both motions had to happen predictably for the mechanism to behave correctly.

Testing and Verification

Validation Was Done in Stages

  1. Initialized and verified MSP432 port configuration to confirm correct motor driver pin usage.
  2. Tested direction control by running the feeder motor forward and reverse.
  3. Verified TimerA PWM output to confirm motor speed control worked as intended.
  4. Tested the servo movement separately to confirm it reached the intended positions consistently.
  5. Tested Dispense_One_Card() with a fixed runtime and adjusted delay and duty cycle values.
  6. Kept the drive motors stopped during dispenser testing so verification could be performed safely.
  7. Confirmed that the software structure could support future states such as ready, players, discard, flop, turn, and river.

Possible Improvements with More Time

Next Iteration Goals

  • Improve the dispenser mechanics so exactly one card is separated and delivered every cycle.
  • Add sensors to detect whether a card actually moved, instead of relying only on motor timing.
  • Complete the full poker dealing state machine for multiple rounds and game phases.
  • Add Bluetooth control so a user could choose the number of players from a phone app.
  • Improve the servo-driven motion so cards could be aimed toward different players more accurately and consistently.

What I Learned

Skills Demonstrated Through This Project

This project brought together hardware troubleshooting, embedded C programming, GPIO control, PWM generation, timer configuration, servo control, and motor-driver integration in one working microcontroller system.

More importantly, it showed how a project moves from idea to implementation: defining a useful task, building a mechanical solution, writing the control logic, testing each subsystem, and refining the design based on real-world behavior.
